# Automation Terminal Approval And Ownership Contract

This update supersedes `02.md` wherever that spec permits continuation
suspensions, non-terminal approval gates, `approved_input`, or client-controlled
side-effect policy.

Automation compilation resolves every connector action through the installed
connector catalog and the builtin permission floor. Node `draft_only` and
`human_approval_required` fields may tighten review requirements but cannot
weaken a server-owned permission. The Automation-level review setting applies
to outward effects, not read-only actions, and cannot disable mandatory review.
Unknown connectors, actions, permissions, and tool effects fail closed.

Every connector action that requires review must be the terminal top-level
step. It may not have a successor or appear inside a loop, branch/join,
first-class Agent, or legacy `puffer_agent` tool call. The compiler does not
emit a continuation checkpoint or resume plan.

First-class Agent and `puffer_agent` steps may declare only connector tools that
trusted catalog policy permits without a review draft. Mandatory-review and
unknown tools are rejected until durable mid-agent approval exists. This update
does not add a general idempotency classification framework.

Connector review metadata is authoritative and defaults to exact approval. An
action may declare ordered editable-text aliases with a maximum byte length and
empty-value policy. Draft creation resolves and stores exactly one field;
conflicting aliases fail closed. All other connector input is immutable.
Product Automation review settings cannot override this metadata or the
permission floor.

The supported live trigger surface in this release is Puffer connector events.
AgentEnv schedule/webhook triggers are rejected. AgentEnv nodes are accepted
only when the selected runtime has an authoritative executable capability;
node discovery alone is insufficient. The current local `transform_js` path is
unsupported.

Runs retain Automation revision and canonical spec hash for audit only. No
normalized definition snapshot, gate sequence, or continuation replay contract
is introduced.

This update does not add schedule/webhook-to-Puffer bridging, loop/agent
approval, arbitrary payload editing, effect inference from client JSON, or
compatibility with the superseded approval metadata.
