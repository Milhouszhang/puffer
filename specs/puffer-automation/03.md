# Automation Execution Ownership And Replay Contract

Automation compilation produces a typed execution plan that identifies the
runtime owner of every trigger and step, the capabilities required from the
selected runtime, and the stable ordering of human-gated action points.

The supported ownership matrix is:

- A Puffer connector-event trigger may enter a mixed Puffer and AgentEnv flow.
- An AgentEnv schedule or webhook trigger may execute an AgentEnv-only flow.
- An AgentEnv-owned trigger followed by `puffer_agent` or a Puffer connector
  action is invalid until a cross-runtime ingress bridge exists.

The compiler and validator reject unsupported ownership combinations before
deployment. Desktop catalog filtering is not a correctness boundary.

Every connector operation with an outward side effect must be represented as a
human-gated action. Gated connector actions inside loop bodies remain invalid.
Until durable mid-agent checkpoints exist, first-class agent steps may expose
only read-only or idempotent tools; side-effecting agent tools are invalid.

Each execution plan assigns a stable gate sequence. A gated action identity is
derived from Automation run ID, step ID, and gate sequence, making draft
materialization idempotent across retries.

A run captures the normalized Automation spec, Automation revision, and
canonical spec hash. A resumed run compiles from this immutable snapshot rather
than the current editable record. Credentials and secret values are resolved at
execution time and are never embedded in the snapshot.

Runtime capability validation distinguishes node discovery from executable
capability. A node advertised by a runtime is not usable unless the runtime can
execute the operation required by the compiled plan. Missing capabilities fail
preview or activation with a stable capability error.

This contract does not add schedule/webhook-to-Puffer bridging, mid-loop
approval, mid-agent approval, arbitrary action payload editing, or compatibility
with the superseded execution metadata schema.
