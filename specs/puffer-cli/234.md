# puffer-cli 234: Runtime-only workflow CLI and daemon handlers

Workflow CLI and daemon handlers no longer expose the old native workflow
store, dry-run, registration, or run-index surfaces.

## CLI

`puffer workflow` now supports only runtime-backed operations:

- `puffer workflow ls [--json]`
- `puffer workflow run <workflow-slug> [--trigger-json ...] [--json]`
- `puffer workflow runs ls <workflow-slug> [--json]`
- `puffer workflow smoke-test [--workflow-id ...] [--json]`

Removed command paths:

- native `register`
- local `dry-run`
- run lookup by native run index

`smoke-test` probes the AgentEnv-compatible runtime without the desktop UI. It
prefers `AGENTENV_API_URL`, `AGENTENV_UI_URL`, `AGENTENV_WORKSPACE_ID`, and
`AGENTENV_API_KEY`, then falls back to `config.workflow_backend` and the saved
workflow-runtime secret. Optional JSON env overrides cover create, execute, and
in-memory execute payloads without making those DTO shapes part of the CLI
contract.

## Daemon

`workflow_list` returns workflows from the configured runtime and keeps the
Puffer-owned connector, binding, monitor, task, and memory context needed by
the desktop UI. It does not load local workflow definitions.

`workflow_save`, native run lookup, and native definition writes are not daemon
routes. Unknown-method handling applies if an old client sends those requests.

`workflow_create`, `workflow_deploy`, `workflow_execute`,
`workflow_list_executions`, and `workflow_get_execution` are daemon RPC
adapters over `WorkflowRuntimeClient`; they do not call the removed native
workflow store or DAG runner.

`workflow_backend_save_config` persists normalized API/UI URLs and
`workspaceId` while storing the API token in the encrypted secret store.
`workflow_backend_get_config` returns only the redacted settings snapshot with
`hasToken`; it never returns the API token or secret id.
`workflow_backend_test_connection` resolves config plus secret-store token,
builds `WorkflowRuntimeClient`, and checks the runtime with the expected
`X-API-Key` and workspace-scoped `X-Workspace-ID` headers.

The daemon WebSocket smoke regression uses a mock AgentEnv HTTP server, saves
settings through RPC, reads the redacted snapshot through RPC, and then tests
connection plus create/deploy/execute/list/get execution through RPC before
checking captured HTTP requests.

## Slash Command And Model Tools

The `/workflows` slash command no longer creates or lists local workflow
definitions. The default dashboard says definitions and execution history live
in the configured workflow runtime while still showing Puffer-owned connector,
connection, action-binding, and monitor-task context.

`/workflows new` and `/workflows create` return a removal message instead of
writing local draft files. Model-visible workflow tools likewise avoid
`WorkflowStore`, `WorkflowDefinition`, and `DagRunner`; they operate only on
subscription workflow bindings, binding history, validation, and
connection-triggered binding creation.

## Subscription Actions

`ActionSpec::RunWorkflow` dispatches to
`WorkflowRuntimeClient::execute_workflow` through the configured backend. The
subscription router passes the matched event envelope as the trigger payload,
and the CLI runner sends it as `{"input": ...}`. There is no fallback to a
local `DagRunner`, cron scheduler, local definition store, or native run index.
