# puffer-cli 247: Automation daemon runtime

## Summary

`puffer-cli` hosts the product-level Automation daemon API. Automations are
stored as Puffer semantic records, compiled into internal AgentEnv workflow
artifacts, deployed explicitly, and previewed only after the current revision is
already synced.

## RPC Surface

The daemon exposes:

- `automation_list`
- `automation_get`
- `automation_save`
- `automation_delete`
- `automation_catalog`
- `automation_compile_deploy`
- `automation_sync_preview`
- `automation_run_preview`
- `automation_run_history`

Automation DTOs expose only record metadata, semantic spec, and a runtime
summary: status, spec hash, compiled revision, AgentEnv workflow count, Puffer
binding count, and last error. Internal workflow ids, binding slugs, and
compiled definitions stay inside runtime state.

## Save And Deploy Contract

`automation_save` is create-or-update. Creates omit `expected_revision`;
updates must supply it. Unknown record-shaped top-level fields such as runtime,
revision, and timestamps are rejected.

Saving a changed spec increments the revision and marks existing runtime state
stale or not compiled. Stale saves remove previously generated Puffer bindings
so old connector filters cannot keep firing changed Automations.

`automation_compile_deploy` is the only daemon route that compiles the current
revision, creates or updates AgentEnv workflow artifacts, deploys them, and
writes live Puffer connector bindings. Failures write runtime `error` with
`last_error` and do not fill successful compile metadata.

## Preview Contract

`automation_sync_preview` prepares the current revision for Test Run without
publishing live triggers. If the current revision is already deployed with a
matching spec hash and compiled workflows, it is a no-op and preserves the live
runtime and binding artifact list. Otherwise it creates or updates AgentEnv
workflow artifacts but does not deploy workflows and does not write Puffer
connector bindings. The stored runtime status is `draft_synced`, with an empty
Puffer binding artifact list.

`automation_run_preview` requires the current revision to have already synced
runtime artifacts (`deployed` or `draft_synced`) and fails before any workflow
runtime request if the runtime is stale, unsynced, missing compiled workflows,
or belongs to another revision.

Preview execution does not require draft artifacts to be deployed. It executes
the freshly compiled root workflow definition through AgentEnv
`execute-in-memory`, passing the selected trigger node id and the same
`{trigger: ...}` input shape used by deployed workflow execution. Manual and
Puffer-owned connection triggers compile into private AgentEnv `webhook`
trigger nodes with deterministic local paths, POST methods, and no
authentication. These generated nodes are internal graph entry points, not
deployed external ingress.

Preview execution rejects connector action steps marked `draft_only`,
`human_approval_required`, or `external_side_effect`; Test Run must not bypass
human-gated outward action policy.

Preview success and error entries are appended to `automation_runs.json` under
the daemon user config directory. History is bounded and responses strip
internal workflow and binding identifiers.

## Error Boundary

Automation compile, preview sync, and preview run RPCs keep raw workflow-runtime
and local-runtime diagnostics in logs, but translate them into product-facing
Automation errors before returning them to Desktop or run history.

User-visible errors must not include runtime URLs, `/v1/...` endpoints, workflow
artifact wording, or local credential internals. Internal compile/test helpers
keep detailed errors for Rust tests and diagnostics. The redaction boundary is
the product Automation daemon API.

Local runtime startup attempts to pull the AgentEnv local runtime image when it
is missing. If an existing image starts but fails compatibility checks, Puffer
attempts to refresh the image once, reruns migrate/seed, and recreates the API
container before returning `incompatible_runtime`. If Docker cannot pull the
image, the status remains `image_missing` or `incompatible_runtime` with a
user-facing installation/update message.

## Catalog And Runtime

`automation_catalog` returns schedule triggers, connector event triggers,
connector actions, and AgentEnv node actions in a UI-oriented shape. Connector
catalog entries include connection state, permission summaries, side-effect
metadata, required inputs, and schemas where available. AgentEnv node discovery
is best effort and reports `agentenv_error` without hiding connector results.
Manual run is returned as a real catalog trigger template so Desktop can create
manual-preview and local-only Automations without an invisible fallback.

Subscription-triggered `RunAutomation` reloads the Automation store from disk
for each run, so daemon saves are visible without restarting the runner. Live
runs require the record to be enabled and use the explicit deployed runtime
path.

Automation compile, preview sync, preview run, and live execution select the
workflow runtime from the persisted Automation `spec.run_location`, not from
the current global workflow backend mode:

- `local` maps to the Puffer-managed local AgentEnv runtime.
- `agent_env_cloud` maps to the configured AgentEnv Cloud runtime.

When an Automation selects local while the user's saved global backend is Cloud,
Puffer starts the local runtime through transient local state under the local
workflow runtime directory. This mutates only the in-memory client config for
that run and does not overwrite the saved Cloud backend config.

First-time local runtime bootstrap treats the default local API URL as
unallocated until Puffer has a complete local runtime identity: a valid
workspace id and stored local runtime token secret. A fresh local runtime
therefore receives an ephemeral loopback port instead of binding
`127.0.0.1:3000`. Existing configured local runtimes keep their saved API URL,
preserving stable runtime references while avoiding collisions with stale or
separately managed AgentEnv containers on port 3000.

The generated Compose file, environment file, seed SQL, saved config, and
secret-vault token must describe the same local workspace. The plaintext
runtime token remains secret-vault only and is not written to config, Compose,
`.env`, or `seed.sql`.

## Smoke Path

`crates/puffer-cli/tests/automation_real_e2e.rs` is an ignored integration test
covering save, compile/deploy, preview, runtime persistence, and public preview
response shape. `scripts/automation-e2e-smoke.sh` is the manual entrypoint.
Local mode uses the Puffer-managed AgentEnv Docker runtime and does not require
user-supplied runtime URLs, workspace ids, tokens, or env vars; the manual cloud
smoke harness requires explicit `PUFFER_WORKFLOW_API_URL`,
`PUFFER_WORKFLOW_WORKSPACE_ID`, and `PUFFER_WORKFLOW_API_TOKEN` to seed its
runtime config. Smoke output must not print tokens.

Local runtime bootstrap writes the AgentEnv gateway encryption and development
gRPC environment required by the local API image, preserving an existing
gateway key when present.
