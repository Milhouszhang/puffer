# Workflow Runtime Backend Config

`PufferConfig` now carries a user-scoped `workflow_backend` block for selecting
the external workflow runtime backend.

- `workflow_backend.mode` is `local` or `agent_env_cloud`.
- Defaults are mode-specific:
  - local: `api_base_url = http://127.0.0.1:3000`,
    `frontend_url = http://localhost:5173`
  - AgentEnv Cloud: `api_base_url = https://api.agentenv.io`,
    `frontend_url = https://agentenv.io`
- `workflow_backend.api_base_url` is normalized to its URL origin before save
  and after load, so inputs such as `https://api.agentenv.io/v1/...` persist as
  `https://api.agentenv.io`.
- `workspace_id` and `api_token_secret_id` are trimmed; the secret id remains
  config-only metadata and never stores token plaintext.
- Layered config loading treats `workflow_backend` like the other user
  preferences that should survive workspace config overlays.

This change is additive. Existing configs without `workflow_backend` keep
loading and default to the local runtime settings.
