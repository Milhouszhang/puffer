# Automation Sidebar Workspace

## Summary

Desktop now has an `Automation` top-level sidebar tab. The screen is a focused
workspace for reviewing saved flows, drafts, starter ideas, and recent
activity without a secondary tab bar.

## Behavior

- `Automation` appears as a first-class sidebar destination between
  `Workflows` and `Tasks`.
- The screen renders a compact header, a left `Saved` list, and a right detail
  panel using existing Puffer desktop tokens.
- The default row is `Review inbox`, and rows can be selected locally to update
  the detail pane.
- Visible UI copy is product-facing: drafts stay editable, users approve
  actions, and repeated work is presented as reviewable queues.
- Internal implementation limits such as preview-only status, missing storage,
  missing triggers, or backend wiring are not exposed in the user-facing UI.
- There are no backend calls, no stored automation definitions, no trigger
  execution, and no connector actions.

## Architecture

`ScreenId` now includes `automation`, `Sidebar.svelte` exposes the navigation
item, and `App.svelte` routes the screen to `Automation.svelte`.
`Automation.svelte` owns static UI data and local selection state so the page
can be tested independently from workflow or monitor backends.

## Compatibility

Existing `Workflows`, `Tasks`, monitor approval behavior, and daemon RPCs are
unchanged. Future backend work must preserve the monitor guardrail that outward
actions are drafted first and executed only after human approval.

## Testing

`tests/automation-ui.spec.ts` covers the sidebar entry, the default
`Review inbox` row, compact visible copy, removal of internal limitation copy,
and the absence of tabs or a canvas surface.
