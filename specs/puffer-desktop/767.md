# Automation List Detail Simplification

## Summary

The desktop Automation screen now follows a simpler Cursor-style list/detail
layout. The previous six-section tab layout was removed because it made the
first version feel like an admin console instead of a focused automation setup
surface.

## Behavior

- The page header keeps the `Automation` title and adds a single
  `New` action.
- The main body is two panes:
  - left: a `Saved` list
  - right: details for the selected automation
- The six local tabs (`Inbox`, `Active`, `Templates`, `History`, `Overview`,
  `Approvals`) are no longer rendered.
- Details use plain sections: `When`, `Then`, `Review`, and `Recent activity`.
- The screen keeps product-facing language and avoids internal implementation
  status. The body does not repeat `Automation` after the top bar and sidebar
  already establish the destination.

## Architecture

`Automation.svelte` now owns a flat list of static `AutomationItem` rows and a
single selected item id. There is no local tab state, tab filtering, or tablist
markup. Selection updates only the right-hand detail pane.

## Compatibility

This remains UI-only. No daemon RPCs, workflow definitions, monitor tasks, or
outward actions are added by this change.

## Testing

`tests/automation-ui.spec.ts` now asserts that the screen exposes
the compact `New` action, the `Saved` list, the selected detail sections, and
no automation tablist.
