# Automation Full Page Creation

## Summary

Clicking `Create automation` in the desktop Automation screen now opens a full-page
`New automation` builder instead of editing inside the home workspace. The sidebar and
top bar remain in place, but the body is dedicated to creation until the user
returns to automations.

## Behavior

- `Create automation` switches the Automation body to a `New automation` page.
- The builder includes a plain-language prompt, starter cards, a name field,
  a readable `When` rule, a `Prepare` field, and explicit review behavior.
- A compact summary states what the automation will do before the user chooses
  `Save paused` or `Create automation`.
- `Automations` returns to the automation home.
- The builder stays UI-only: buttons update local screen state only and do not
  create stored definitions or trigger outward actions.

## Architecture

`Automation.svelte` owns a local `screenMode` state with `home` and `new` views.
Starter data is static and updates local form fields when selected. The new
view replaces the automation home rather than rendering a modal, side panel, tab,
or canvas.

## Compatibility

Existing sidebar navigation and desktop daemon APIs are unchanged. Future
backend work should attach to the create action without changing the full-page
layout contract.

## Testing

`tests/automation-ui.spec.ts` covers the create path, asserts the `New automation`
page is shown, verifies home list/detail content is not rendered in that state,
and checks that returning to automations restores the home.
