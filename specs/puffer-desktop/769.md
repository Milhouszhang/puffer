# Automation Prompt-First Home

## Summary

The desktop Automation destination now opens on a prompt-first automation home.
The top of the page lets the user describe an automation in plain language, and the
lower section displays available automations as compact cards.

## Behavior

- The home view shows `Create an automation` and the original Puffer composer
  element structure.
- Template cards such as `Review PRs`, `Reply drafts`, `Calendar RSVP`, and
  `Morning digest` open the full-page `New automation` builder with matching
  starter content.
- Text entered in the home prompt carries into the `New automation` builder.
- The `Automations` section replaces the earlier saved-list/detail home and
  separates user-created automations from templates.
- The page avoids secondary tabs, selected-detail panels, canvas language, and
  implementation-only copy.

## Architecture

`Automation.svelte` keeps local-only UI state with `screenMode` values of
`home` and `new`. Static starter data powers template cards. Static automation
card data renders the user automation grid. No daemon RPC, storage, or
execution contract is added.

## Compatibility

The existing sidebar entry and desktop shell remain unchanged. The full-page
builder contract from the previous spec remains intact: creation replaces the
home until the user chooses `Automations` to go back.

## Testing

`tests/automation-ui.spec.ts` verifies the prompt-first home, original composer
structure, separated `Your automations` and `Template Library` lists, absence of
tab/detail/canvas surfaces, prompt handoff into the builder, and return
navigation back to `Automations`.
