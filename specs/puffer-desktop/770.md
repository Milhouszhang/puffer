# Automation Home Library Split

## Summary

The Automation home now matches the Langdock automation home pattern more closely:
the prompt uses Puffer's original composer element structure, and the automation
library is split between user-created automations and templates.

## Behavior

- The home prompt uses the same composer elements as the main Puffer input:
  attachment control, model picker, fast toggle, thinking selector, permissions
  selector, keyboard hint, and send button.
- `Your automations` lists user-owned automation cards.
- `Template Library` lists starter cards powered by the same starter definitions used
  in the new automation builder.
- Clicking a template card opens the full-page `New automation` builder with that
  template selected.
- The page still avoids secondary tabs, detail panes, and canvas surfaces.

## Architecture

`Automation.svelte` imports the shared chat composer stylesheet and keeps the
home split local to static UI data. `userAutomations` filters the existing automation card
data, while `automationTemplates` renders template cards. No backend, storage,
or execution wiring is introduced.

## Compatibility

The sidebar entry, top bar, and full-page builder remain unchanged. Tests now
target the more explicit library structure rather than a single mixed automation
list.

## Testing

`tests/automation-ui.spec.ts` covers the original composer element structure,
checks `Your automations` and `Template Library`, covers template-card
navigation into `New automation`, and keeps the existing no-tabs/no-canvas
constraints.
