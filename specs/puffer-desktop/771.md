# Automation Home Composer Parity

## Summary

The Automation home now uses the original Puffer composer structure instead of
a custom automation prompt surface. The library below follows the Langdock home
layout with a user automation section and a template library section.

## Behavior

- The top composer includes the same visible controls as the main Puffer
  composer: add content, model picker, fast toggle, thinking selector,
  permissions selector, keyboard hint, and send button.
- Starter chips are removed from the composer area.
- `Your automations` lists user-owned cards.
- `Template Library` lists template cards and opens the full-page
  `New automation` builder when selected.

## Architecture

`Automation.svelte` keeps the composer local and static for this UI-only pass,
but mirrors the element order and classes used by the main conversation
composer. The lower library remains static data driven through `userAutomations`
and `automationTemplates`.

## Compatibility

No backend, storage, daemon RPC, or send behavior is added. The send button only
opens the existing UI-only builder.

## Testing

`tests/automation-ui.spec.ts` verifies the composer wrapper, attachment input,
add button, model picker trigger, fast toggle, thinking selector, permissions
selector, keyboard hint, send button, `Your automations`, and
`Template Library`.
