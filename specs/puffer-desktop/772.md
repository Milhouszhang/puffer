# Automation Cursor-Style Creation Page

## Summary

The desktop Automation create screen now follows Cursor's single-page creation
layout while keeping Puffer's shell, composer language, controls, borders, and
spacing. Creation stays inside the Automation destination and does not introduce
a canvas, modal, or secondary tab set.

## Behavior

- Sending from the home composer or selecting a template opens the full-page
  create screen.
- The top of the create screen shows a breadcrumb back to `Automations`, plus
  `Cancel` and `Save` actions.
- The form is ordered as `Name`, `Triggers`, `Instructions`, `Tools`, and
  `Cloud Agent Environment`.
- `Triggers` shows a selected PR trigger row, an `Add Trigger` row, and a
  Cursor-style trigger menu with scheduled and GitHub / GitLab options.
- `Instructions` uses one large prompt field with the model selector below it.
- `Tools` includes `Memories`, `Manage`, `Add Tool or MCP`, and a common-app
  picker for selecting familiar app integrations.
- `Cloud Agent Environment` includes the configured environment row, `Manage`,
  and an enabled switch.

## Architecture

`Automation.svelte` still owns local UI-only state. Template cards populate the
name, instruction, and trigger fields through static starter data. The trigger
menu stores the selected trigger locally. `Save` adds a local automation card
for the current UI session only and does not call daemon APIs.

## Compatibility

The Automation sidebar destination, top bar, and home composer remain unchanged.
No backend, storage, daemon RPC, or automation execution contract is added.
Future backend work can attach to `Save`, trigger rows, and template data
without changing the single-page layout contract.

## Testing

`tests/automation-ui.spec.ts` covers the home composer, library split, create
page structure, prompt handoff, template handoff, Cursor-style trigger menu,
absence of tabs/detail/canvas surfaces, and back navigation to the Automation
home.
