# Automation Tools App Picker

## Summary

The Automation create page now expands `Add Tool or MCP` into a common-app
picker. The picker gives users familiar app choices before backend integration
is available.

## Behavior

- Clicking `Add Tool or MCP` opens a `Common apps` menu.
- The menu lists GitHub, Slack, Gmail, Google Calendar, Linear, and Notion.
- Selecting an app adds it to the local `Tools` section as a configuration row.
- Tool rows show the app name and the API capabilities that the automation can
  use, such as pull requests, issues, commit status, read threads, or create
  drafts.
- Each selected tool row has an `APIs` entry that opens the capability picker
  for that app.
- Selected tool rows can be edited to replace the app or removed from the
  current draft.
- Selected apps are local UI state for the current create session only.
- Opening a blank automation, template automation, or existing automation resets
  selected app state.

## Architecture

`Automation.svelte` keeps a static `commonApps` list and local
`selectedToolApps` state. Each app includes a static capability label list, and
each selected row stores the capabilities currently enabled for that draft.
Editing a selected row records the app id being replaced and reuses the
common-app picker. The menu uses the same popover style as the trigger picker
and does not call daemon APIs, install MCP servers, or request credentials.

## Compatibility

No storage, daemon RPC, connector, or MCP execution contract is introduced. A
future backend can map the static app entries to real app connectors or MCP
servers while preserving the create-page layout.

## Testing

`tests/automation-ui.spec.ts` verifies that clicking `Add Tool or MCP` opens
the `Common apps` menu, shows the common app options, and renders selected app
capabilities in the `Tools` section. It also verifies replacing and removing a
selected app row and selecting app API capabilities.
