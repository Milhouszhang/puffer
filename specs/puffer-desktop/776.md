# Natural Language Automation Drafts

## Summary

The Automation home composer now starts automation creation from plain user
intent. Sending a prompt opens the full-page create page with a reviewable draft
configuration instead of an empty builder.

## Behavior

- The home placeholder asks users to tell Puffer what to automate and gives a
  PR-review example.
- Sending non-empty composer text opens the create page.
- The original composer text is preserved in `Instructions`.
- Known prompt patterns pre-fill the automation name, trigger row, and common
  app rows for review. Current local patterns include PR review, calendar RSVP,
  email reply, Slack reply, and morning digest.
- Prompts that do not match a known pattern still open the create page with the
  user's instructions preserved, so the user can finish the configuration.
- `Save` and `Cancel` continue to be the only top-level create-page actions.

## Architecture

`Automation.svelte` keeps this as local UI state. `draftFromPrompt` maps the
composer text to a small draft object containing a name, instructions, optional
trigger, and selected app rows. It does not call a model, daemon API, storage,
connector, or MCP server.

## Compatibility

This is a UI-only creation affordance. Future backend work can replace the
static draft mapping with a real automation planning contract while preserving
the same review-before-save page.

## Testing

`tests/automation-ui.spec.ts` verifies the user-facing placeholder and the PR
prompt path: sending from the home composer opens the create page with the PR
name, trigger, instructions, and GitHub app pre-filled.
