# Automation Tool Capability Rows

## Summary

The Automation create page now shows selected tools as reviewable app rows with
their available API capabilities. This makes the `Tools` section match the
plain-language trigger rows instead of showing app names alone.

## Behavior

- The default `Memories` row shows a `Read context` capability.
- Selected app rows show the app name on the left and capability tokens on the
  right.
- GitHub shows `Pull requests`, `Issues`, and `Commit status`.
- Gmail shows `Read threads`, `Create drafts`, and `Labels`.
- Slack, Google Calendar, Linear, and Notion also carry static capability
  labels for the create-page UI.
- Selected app rows include an `APIs` entry that opens a checkbox menu for
  choosing which capabilities are enabled.
- Selected app rows include edit and remove controls.
- The `Add Tool or MCP` menu behavior is unchanged.

## Architecture

`AutomationApp` now includes a static `capabilities` list. Selected rows keep a
local `selectedCapabilities` list that defaults to all app capabilities.
`Automation.svelte` renders the selected labels in the `Tools` rows using the
same token styling as trigger parameters. Selected rows use local state for
choosing API capabilities, replacing one app with another, and removing an app
from the current draft. The data remains component-local and UI-only.

## Compatibility

No backend permissions, connector APIs, MCP installation, or credential setup is
introduced. Future backend work can replace the static labels with real
connector capability metadata while preserving the selected-row layout.

## Testing

`tests/automation-ui.spec.ts` verifies that a natural-language PR automation
shows GitHub with pull request, issue, and commit status capabilities, and that
adding Gmail shows email thread and draft capabilities. The same test verifies
opening the `APIs` picker, unselecting a GitHub capability, editing GitHub into
Gmail, and removing Gmail from the selected tools.
