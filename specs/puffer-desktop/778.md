# Automation Draft Row Editing

## Summary

The Automation create page now lets users modify or remove rows that have
already been added to the draft. Triggers and selected tools are no longer
read-only once they appear in the builder.

## Behavior

- A selected trigger row has edit and remove controls.
- Editing the selected trigger reopens the trigger picker and replaces the
  current trigger when the user chooses another option.
- Removing the selected trigger clears the row and leaves `Add Trigger`
  available.
- A selected tool row has edit and remove controls.
- Editing a selected tool reopens the common-app picker and replaces that row
  with the newly selected app.
- Removing a selected tool deletes only that app row from the current draft.
- The default `Memories` row remains visible as base context and is not
  removable in this UI pass.

## Architecture

`Automation.svelte` keeps trigger editing local by reopening the existing
trigger menu. Tool editing uses a local `editingToolAppId` state value so the
same app picker can either add a new app or replace one selected app. Removal is
local component state only.

## Compatibility

No backend storage, connector permission, MCP installation, or execution
contract is introduced. Future persistence can store the final selected trigger
and tool rows without changing this edit-before-save interaction.

## Testing

`tests/automation-ui.spec.ts` verifies editing and removing a selected trigger,
editing GitHub into Gmail, removing Gmail, and adding Gmail again from the app
picker.
