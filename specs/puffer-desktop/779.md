# Automation Tool API Picker

## Summary

Selected tools now expose a visible `APIs` entry so users can choose which app
capabilities the automation is allowed to use. Capability tokens are no longer
only static display text.

## Behavior

- Each selected app row shows an `APIs` button next to the edit and remove
  controls.
- Clicking `APIs` opens a checkbox menu named for that app's API capabilities.
- Capabilities are selected by default when an app is added or inferred.
- Unchecking a capability removes that token from the selected tool row.
- Replacing a tool resets the new app to its default selected capabilities.

## Architecture

`SelectedAutomationApp` extends the static app metadata with a local
`selectedCapabilities` list. `capabilityMenuAppId` controls which app's
capability menu is open. Toggling a checkbox updates only local component
state; no daemon, MCP, connector, permission, or persistence call is made.

## Compatibility

This remains a UI-only draft affordance. Future backend work can map selected
capability labels to real connector scopes or MCP tool names without changing
the visible `APIs` entry.

## Testing

`tests/automation-ui.spec.ts` verifies that GitHub shows a `Select GitHub APIs`
entry, opens a capability checkbox menu, defaults capabilities to checked, and
removes the `Issues` token when it is unchecked. The test also verifies that a
newly added Gmail tool exposes `Select Gmail APIs`.
