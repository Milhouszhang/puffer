# Automation Tool Picker Capabilities

## Summary

The Automation create page now shows app API capabilities directly inside the
`Add Tool or MCP` picker. Users can add an app by selecting the app row, or add
and edit a narrower set of abilities by checking capabilities under that app.

## Behavior

- The tool picker keeps the trigger-picker structure: search field, `Common
  apps` label, app rows, and compact choices under each app.
- Each app group lists its API capabilities below the app description.
- Checked capabilities reflect the currently selected tool row immediately.
- Checking a capability for an unselected app adds that app with only that
  capability selected.
- Clicking an app row still selects all default capabilities for that app.
- Selected tool rows no longer expose a separate `APIs` button.
- Existing selected tools remain editable and removable before save.

## Architecture

`Automation.svelte` keeps app metadata in `commonApps` and selected draft state
in `selectedToolApps`. The picker reads and writes the same
`selectedCapabilities` list that selected rows render as tokens. Search remains
local to the picker and matches app names, descriptions, and capability labels.

## Compatibility

This is still UI-only. No connector permission, MCP install, daemon RPC,
credential, or persistence behavior is introduced.

## Testing

`tests/automation-ui.spec.ts` verifies that the picker shows per-app capability
groups, that GitHub capabilities are checked for a prompt-created PR
automation, that unchecking `Issues` updates the GitHub row, and that checking
Gmail `Create drafts` adds Gmail without showing a selected-row `APIs` button.
