# Automation Tool Capability Items

## Summary

The Automation create page now treats each app capability as its own selected
tool item. A user adds `Send to Slack`, `Comment on Pull Request`, or `Create
Gmail Draft` directly, rather than adding one app row that aggregates several
capabilities.

## Behavior

- The `Add Tool or MCP` picker still groups capabilities by app.
- Each capability is a separate selectable menu item under its app group.
- Selected capabilities render as separate rows in `Tools`.
- Rows use sentence-like copy: capability title first, then an optional target
  phrase.
- Capabilities with a destination or mode show a target chip, such as `to
  #teams`, `with Allow PR Approval`, or `in Primary inbox`.
- Clicking a target chip cycles through local placeholder options.
- Editing a selected row opens the picker and replaces that row with the next
  selected capability.
- Removing a row deletes only that capability item.

## Architecture

`AutomationCapability` stores the capability title, description, optional target
label, target options, and default target. `SelectedAutomationTool` is the local
draft row shape used by the create page. Prompt inference now seeds selected
capability ids, not app ids.

All state remains component-local in `Automation.svelte`. No backend connector,
MCP, permission, credential, or persistence contract is introduced.

## Testing

`tests/automation-ui.spec.ts` verifies that a PR prompt creates a `Comment on
Pull Request` row with an `Allow PR Approval` target, that the picker exposes
capabilities as individual menu items, that selecting `Send to Slack` creates a
separate `#teams` row, and that editing/replacing/removing selected capability
items works without showing a selected-row `APIs` button.
