# Automation Terminal Review UI

This update supersedes `792.md` where Desktop exposes raw connector input,
sends `approved_input`, or uses `connector_action_execute` and
`automation_pending_action_reject`.

The review inbox continues to use `automation_pending_action_list` and
`automation_pending_action_get`. Detail contains the server-selected approval
policy, editable text, and sanitized action/destination fields; it never contains
raw connector input or mutable provenance/routing fields.

An `editable_text` action shows one text editor. An `exact` action is read-only.
Desktop sends optional `approved_text` through `outbound_action_execute` and
uses `outbound_action_cancel` for rejection. Automation cancellation requires a
non-empty reason. Compatibility wrappers are removed.

The builder permits at most one mandatory-review action and keeps it as the
terminal top-level step. Server validation remains authoritative.

A sent action immediately leaves the inbox. If terminal run settlement is
temporarily stale, Desktop may show "Sent; updating run history" and refresh
history, but it never offers resend or continuation retry.

An uncertain action explains that delivery may already have occurred. Retrying
requires duplicate-risk acknowledgement. Abandoning further attempts requires a
separate delivery-risk acknowledgement and is displayed as failed with possible
delivery, never as ordinary rejection. Expired approvals have a distinct failed
outcome.

The builder does not show schedule/webhook triggers or actions the selected
runtime cannot authoritatively execute. The current local JavaScript Transform
is hidden. Client filtering is supplementary; save/activation errors remain
authoritative. Active is shown only after final activation success, and a
runtime-target mismatch requires reactivation.

Desktop UI coverage includes editable approval, exact approval, normal
rejection, same-request behavior, uncertain retry/abandon acknowledgement,
sent-with-delayed-terminal-settlement refresh, expiry, hidden unsupported
catalog entries, and active-run deletion errors. The existing review-inbox
`test.fixme` is restored, and fake daemons continue to reject unknown RPCs.
