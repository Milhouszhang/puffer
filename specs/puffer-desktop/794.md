# Automation Review And Runtime Capability UI

The Automation review inbox renders the daemon-provided approval policy. An
`editable_text` action shows one text editor. An `exact` action shows only
sanitized action and destination fields and cannot submit edited connector
input. Desktop sends optional `approved_text`; it never sends a full approved
payload, origin metadata, routing fields, or connector identity.

Automation approval and rejection use the canonical
`outbound_action_execute` and `outbound_action_cancel` RPCs. Compatibility
wrappers and legacy mutation aliases are removed. Rejection requires a non-empty
reason.

Execute responses present action delivery separately from Automation run
settlement. A sent action immediately leaves the review inbox. If its run is
`resume_pending`, Desktop reports that delivery succeeded and the Automation is
continuing. Run history exposes Continuing and Needs attention states and an
explicit retry action. Desktop must never suggest resending an action merely
because continuation settlement failed.

An `uncertain` action clearly states that delivery may already have happened.
Retry remains disabled until the reviewer acknowledges duplicate-send risk.

The Automation builder displays only trigger and action capabilities returned
as executable by the daemon. The current product surface does not show schedule
or webhook triggers, and does not show Local JavaScript Transform when the
selected runtime lacks its executor sandbox. Client filtering is supplementary;
save, preview, and activation errors remain authoritative.

The Active state is shown only from the final successful activation response.
Changing runtime configuration or receiving a stale-backend/capability error
returns the Automation to a state requiring activation.

Desktop UI coverage includes editable approval, exact approval, rejection,
uncertain delivery acknowledgement, sent-plus-resume-pending feedback, recovery
retry, hidden unsupported catalog entries, and active-run deletion errors. The
existing review-inbox `test.fixme` is restored as an executable Playwright test,
and fake daemons continue to reject unknown RPC methods.
