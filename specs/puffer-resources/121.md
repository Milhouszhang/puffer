# Deterministic External Resource Discovery

## Summary

External Claude Code / Codex resource discovery no longer walks the whole
`~/.claude` and `~/.codex` trees recursively. Skills and commands now load
from fixed roots, and installed Claude plugins resolve through
`~/.claude/plugins/installed_plugins.json` (schema version 2) via the new
`plugin_manifest` module. A malformed third-party file can no longer abort
`load_resources`; it degrades to a `LoadedResources.diagnostics` entry.

## Contract

- External skills load from `<root>/skills/<name>/SKILL.md` (one level
  deep); external commands load from `<root>/commands/` (Claude style,
  nested subdirectories allowed) or `<root>/prompts/` (Codex style).
- Fixed roots, lowest merge priority first: manifest plugin roots, user
  `~/.claude`, user `~/.codex`, workspace `.claude`, workspace `.codex`.
  Workspace `.puffer/resources` merges after all external sources and wins.
- Only `installed_plugins.json` decides which cached plugin versions are
  live; unreferenced `plugins/cache` directories are never scanned and
  produce no diagnostics.
- Every external read or parse failure (unreadable file, bad frontmatter,
  unreadable directory entry, corrupt manifest) is a non-fatal diagnostic.
  Puffer-owned resources (`~/.puffer`, embedded, workspace `.puffer`)
  keep fail-fast semantics.
- Command scans skip junk directories (`.git`, `node_modules`, `target`,
  `dist`, `build`, `.next`, `.svelte-kit`) and never follow symlinked
  directories, so symlink cycles cannot hang startup. Symlinked skill
  directories and command files still load.
