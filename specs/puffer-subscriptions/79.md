# puffer-subscriptions 79: AgentEnv workflow action trigger contract

`puffer-subscriptions` now models `run_workflow` actions as AgentEnv runtime
workflow executions while preserving the existing binding JSON field name.

## Action Contract

`ActionSpec::RunWorkflow` stores its Rust field as `workflow_id`. The serialized
JSON remains:

```json
{"type":"run_workflow","slug":"<workflow-runtime-id>"}
```

The `slug` JSON field is compatibility-only. Its value is the workflow id
returned by the configured AgentEnv-compatible runtime, not a Puffer-local node
id, connector node id, binding slug, or human-readable workflow name.

Validation accepts non-empty URL-safe runtime ids, including common AgentEnv id
characters such as uppercase ASCII letters, digits, `-`, `_`, `.`, and `:`.
Binding slugs, connection slugs, and connector slugs keep their stricter
kebab-case Puffer validation.

## Trigger Payload

When a connector event dispatches a run-workflow binding,
`BuiltinActionDispatcher` calls the installed `WorkflowActionRunner` with the
configured runtime workflow id and this connection trigger object:

```json
{
  "type": "connection",
  "envelope_id": "...",
  "connection_id": "...",
  "receivedAt": "...",
  "topic": "...",
  "kind": "...",
  "dedup_key": "...",
  "text": "...",
  "payload": {}
}
```

The original event payload is preserved under `payload`, and the router does
not rename `receivedAt` or add millisecond shadow fields.

## Router Integration

Router coverage includes the in-process path from a Telegram-style
`EventEnvelope` to a bound workflow runner. The event topic and subscriber id
identify the `telegram-user` connection, filters such as `.chat_id == 424242`
must match before dispatch, and the runner receives the same workflow id that
the CLI runtime later uses in `/v1/workflows/:workflow_id/execute`.

Generic connector actions share the same router path. `connector_act` bindings
dispatch into the installed `ConnectorActionExecutor` with connector slug,
action slug, rendered input JSON, and the same connection trigger payload.
String templates in connector action input render from `{{text}}` and
`{{payload.path}}` before executor invocation.

Include filters remain authoritative before action dispatch. If a binding
filter does not match an event, neither workflow runners nor connector
executors are invoked.
