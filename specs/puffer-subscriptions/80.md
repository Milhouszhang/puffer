# puffer-subscriptions 80: RunAutomation dispatcher

## Summary

`ActionSpec` includes `RunAutomation { automation_id }` as the connector
binding entry point for product-level Automations. It stores only the stable
Puffer Automation id and does not expose Automation specs, AgentEnv workflow
definitions, or AgentEnv workflow ids.

## Runtime Contract

`WorkflowActionRunner` provides `run_automation(automation_id, trigger)`.
Existing runner implementations continue to compile because the default method
returns a clear "not installed" error.

`BuiltinActionDispatcher` recognizes `RunAutomation`, renders the same
connection trigger payload used by `RunWorkflow`, and passes it to the injected
runner hook. The result is converted through `ActionResult::success_from_output`
so usage and timing fields are preserved when provided by the runner.

## Boundary

`puffer-subscriptions` remains the connector binding and dispatch crate. It
validates the Automation id, routes the event through an injected runner, and
does not depend on `puffer-automation` or inspect Automation runtime state.
Outward effects remain governed by the existing monitor/action approval paths.
