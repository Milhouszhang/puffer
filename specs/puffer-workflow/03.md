# puffer-workflow update 03

`puffer-workflow` now models the AgentEnv workflow definition structure that is
shared by Puffer editors and AgentEnv runtimes.

## Shared Definition Contract

The shared graph JSON is:

- `definition.nodes[]`
  - `id: string`
  - `type: string`
  - optional `name: string`
  - `config: object`
  - optional `trusted: boolean`
  - optional `position: { x: number, y: number }`
- `definition.edges[]`
  - `source: string`
  - `target: string`
  - optional `conditionScript: string`

Puffer owns this structural contract only. Node `config` remains opaque JSON and
is validated by AgentEnv node definitions and runtime validation.

## Runtime Requests

Typed request DTOs now mirror AgentEnv:

- create: `{ name, description?, definition }`
- update: `{ name?, description?, definition?, status? }`
- in-memory execute: `{ definition, input?, triggerNodeId? }`

The runtime client accepts typed DTOs for create/update/in-memory execution and
continues to accept generic records for deployed workflow execution input.

## Runtime Surface

The client now exposes the editor/runtime endpoints needed by Desktop:

- `GET /v1/workflows/node-definitions/:type`
- `PUT /v1/workflows/:id`
- `POST /v1/workflows/:id/undeploy`

The existing in-memory endpoint is corrected to send AgentEnv's actual
`definition` payload instead of an opaque `workflow` object. Local AgentEnv
Docker and AgentEnv Cloud use the same API shape; Puffer changes only runtime
base URL, token, and workspace id.
